# Release Notes – PlantBot Bewässerung **1.2.10-beta**

**Datum:** 2026-08-29  
**Basis:** Alle Änderungen seit **v1.2.9** (29. März 2026), inkl. der Alpha-Stufe.  
**Voraussetzung:** Plantbot-Firmware **≥ 1.3.0-gamma** ([plantbot-OTA](https://github.com/fabibo89/plantbot-OTA/releases/tag/v1.3.0-gamma)).  
**Hinweis:** Pre-release – bitte mit passender Firmware testen.

## Zugehörige Firmware

Diese HA-Version ist auf **Firmware ≥ 1.3.0-gamma** ausgelegt (MQTT-Status mit `latest_version` / `update_needed`, plus die Alpha-Themen `valves` und `status_request`).

→ **[plantbot-OTA v1.3.0-gamma](https://github.com/fabibo89/plantbot-OTA/releases/tag/v1.3.0-gamma)**

**Wichtig – SPIFFS / Web-Dateien:** Ein Firmware-OTA aktualisiert **nur** die Firmware, **nicht** die Dateien im SPIFFS (Web-UI unter `/control`, `/config`, `/manager`, …). Nach dem Firmware-Update die Dateien aus dem Release-Asset **`spiffs-data.zip`** (Ordner `Updater/`) auf die Station nachladen – Details in den Firmware-Release-Notes.

## Features (seit v1.2.9)

- **Live-Daten per MQTT statt HTTP-Polling:** Sensoren, Status und Ventile kommen über MQTT (`sensors` / `status` / `valves`). HA sendet beim Start und alle 5 Min `commands/status_request` für einen Snapshot.
- **Availability über MQTT-Heartbeat:** Station gilt als online, solange Nachrichten kommen (`last_mqtt_seen`, Timeout 120 s) – kein Flackern mehr durch kurze `/status`-Timeouts.
- **OTA-Update-Status via MQTT:** Firmware-Update-Fortschritt wird live über MQTT übernommen; HTTP `/update_status` bleibt Fallback.
- **Firmware-Update-Info per MQTT:** Coordinator übernimmt `latest_version` und `update_needed` aus `plantbot/{ip}/status`. Die Update-Entity zeigt verfügbare Updates, ohne HTTP-`/status` zu pollen. Sensor **„Update erforderlich“** wird immer angelegt.
- **Wasseroberfläche-Sensor:** Neuer optionaler Sensor `water_surface_cm` (Abstand Sensor → Oberfläche). Wasserstand: Icon `mdi:waves`, Wasseroberfläche: `mdi:arrow-expand-vertical`.
- **Stations-Metriken per MQTT-Status:** Flow, Volume, Wasser-Runtime, Letzter Reset Grund (wie früher HTTP `/status`).
- **Event `plantbot_watering_finished`:** Nach Server-Gießjobs (`job_id > 0`) inkl. `plant_name`, Mengen, Status (nur Server-Betrieb).
- **Release Notes in der UI:** Volle Versionshinweise + kurze `release_summary`-Vorschau (255 Zeichen, `HA_SUMMARY`).

## Fixes / Robustheit

- **„No update available“ / Flackern bei transienten Fehlern:** Stationen behalten den letzten gültigen Zustand bei kurzzeitigen Timeouts/Neustarts.
- **Offline ohne Error-Tracebacks:** Kurze Offline-Phasen werden als offline behandelt, nicht als harter Coordinator-Fehler.
- **Per-Station Availability:** Entities orientieren sich an der jeweiligen Station (`available`), nicht global an `last_update_success`.
- **MQTT-Livedaten überleben Server-Refresh:** Sensoren/Status gehen beim periodischen API-Poll nicht verloren; Fallback über Server `last_value`, wenn MQTT noch leer ist.

## Verbesserungen

- **Buttons refaktoriert (`PlantBotHttpButton`):** Generische HTTP-GET-Buttons; Reset bleibt.
- **Update-Dialog stabiler:** Status bevorzugt aus MQTT, HTTP nur noch Fallback.
- **Coordinator:** Server-Metadaten (Pflanzen, Jobs, …) weiter per API (60 s); Geräte-Live-Daten primär MQTT.
- **README** mit Setup, Architektur, Services, Events und Troubleshooting.

## Breaking / Voraussetzung

- **Benötigt Plantbot-Firmware ≥ 1.3.0-gamma** für vollständige MQTT-Livedaten und die Update-Anzeige in HA.
  - ≥ 1.3.0-alpha: `…/valves`, `…/commands/status_request`
  - ≥ 1.3.0-gamma: `latest_version` / `update_needed` im MQTT-Status
- **SPIFFS-Dateien aktualisieren:** OTA ersetzt nicht die Web-UI – `spiffs-data.zip` aus dem Firmware-Release nachladen.
- HTTP `GET /status` wird für den Normalbetrieb nicht mehr alle 30 s gepollt (OTA/Reset weiter HTTP).
- Nach dem HA-Update die Integration **neu laden**.

## Bekannte Hinweise

- Direkte Ventilbefehle aus HA (`job_id < 0`) erzeugen **kein** ACK und **kein** `plantbot_watering_finished`.
- Ältere Firmware ohne erweiterte Status-Felder: Flow/Volume/Runtime/Reset-Grund bzw. Update-Info bleiben „Unbekannt“.
